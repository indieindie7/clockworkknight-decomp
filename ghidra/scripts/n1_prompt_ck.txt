Sega Saturn game Clockwork Knight 2 (Sega CS2, Japan GS-9029 "Pepperouchau no Daibouken Gekan" 1995-07; SH-2 code, likely Hitachi SHC or GNU). One program A.BIN (the boot program) loaded at 0x06003000; level overlays AREA<n><x>.BIN, WMAP*.BIN, SELECT.BIN etc. are loaded by it at a fixed address (find it: pointers near 0x0603b400 are a candidate). Research only. Game: 2.5D side-scrolling platformer; Pepperouchau the wind-up toy knight walks, jumps, attacks with his key, winds up enemies, picks up and throws objects (the throw/carry system is the research focus), rides toy vehicles; areas are rooms with sprite objects (VDP1 sprites, scaled/rotated), VDP2 scroll backgrounds, boss fights, a world map, bonus and result screens, 2-player versus. Focus names on player state and input, carry/throw, enemy objects, collision, camera scroll, sprite drawing, overlay/file loading, sound commands.

Task: name functions from the Ghidra decompile. FILE holds the decompile of a slice of the functions of A.BIN. Name EVERY function in FILE whose name is still FUN_xxxxxxxx (skip ones that already have a name).

Evidence to use: strings, called functions (names given by earlier slices), Saturn hardware registers, how the function uses its arguments. Saturn memory map: 0x25c00000 VDP1 VRAM (command table), 0x25d00000 VDP1 regs (TVMR 0x25d00000, FBCR 02, PTMR 04, EWDR 06, EWLR 08, EWRR 0a, ENDR 0c, EDSR 10), 0x25e00000 VDP2 VRAM, 0x25f00000 VDP2 color RAM, 0x25f80000 VDP2 regs, 0x25a00000 sound RAM (68000), 0x25b00000 SCSP regs, 0x25fe0000 SCU (DMA 0x25fe0000-0x25fe0060, interrupt mask 0x25fe00a0, status a4), 0x20100000 SMPC (COMREG 0x2010001f, SR 0x20100061, SF 0x20100063, IREG 0x20100001.., OREG 0x20100021..), 0x25890000 CD block (HIRQ 0x25890008, CR1-4 0x25890018..24), 0xfffffe00..0xffffffff SH-2 on-chip (FRT, DIVU 0xffffff00, DMAC 0xffffff80, cache 0xfffffe92), 0x21000000/0x21800000 slave SH-2 FRT input-capture (master-to-slave command), 0x06000000 BIOS work area (0x06000300.. BIOS vectors), 0x00000000 BIOS ROM. Fixed-point math: GCC calls to library helpers, 16.16 FIXED values; SGL calls such as slInitSystem, slSynch, slPutPolygon, slPushMatrix/slPopMatrix, slTranslate, slRotX/Y/Z, slSetSprite, slPrint, slDMACopy, slCdChgDir-style CD calls (GFS: GFS_Init, GFS_NameToId, GFS_Open, GFS_Fread, GFS_Load; CDC_* low level) may be recognisable by behaviour. Sonic R uses Travellers Tales own engine, not SGL; only use an SGL/SBL API name when the behaviour clearly matches (say why in the comment); otherwise give a descriptive name.

Naming style: lowercase module prefix + CamelCase verb, e.g. vdp1_ClearCommands, cd_ReadSectors, pad_ReadDigital, car_UpdatePhysics, menu_DrawCursor, math_FixedMul, mem_Copy. C runtime copies: memcpy/memset/strcpy/sprintf etc. with plain names. Tiny stubs that only return: stub_<addr>. When unsure, still give the best descriptive name and add "provisional" at the start of the comment.

Output: write lines to OUT (create it with Write; one line per function, no other text):
0x<addr> func <name> hand <comment of 5-20 words: what it does, key callees, registers or strings>
Addresses as 8 lowercase hex digits (e.g. 0x06012a3c). Names must be unique within OUT; append _2, _3 when two functions would share a name. Do not read files other than FILE. Read FILE in pieces (offset/limit, about 600 lines at a time) until the end. Reply at the end with only the line count.
